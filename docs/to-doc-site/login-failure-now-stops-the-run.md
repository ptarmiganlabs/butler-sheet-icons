# A failed login now stops the run instead of capturing the login screen

If Butler Sheet Icons could not sign in to Qlik Sense, it used to carry on regardless. The browser
stayed on the login page, and BSI photographed that page once per sheet, uploaded those images as
sheet thumbnails, and reported the run as successful.

The result was an app whose every sheet showed a picture of a login form, and a scheduled job that
said nothing was wrong.

Butler Sheet Icons now checks that the login actually worked, and stops if it did not — before it
uploads anything, and before it changes a single sheet.

::: warning Requires BSI 5.0.0 or later
In earlier versions a failed login produced thumbnails of the login screen and a successful-looking
run.
:::

## What you will see

The run stops at startup with an error naming what it expected. On Qlik Sense Enterprise on Windows:

```
QSEOW APP: not authenticated after submitting the credentials and waiting for navigation. The login
form's username field (#username-input) is still on the page, so the browser is on the login screen.
Continuing would capture that screen as though it were a sheet. Check the username and password
supplied to BSI, and that the login page is the form this strategy expects.
```

On Qlik Sense Cloud the message is the same, naming that platform's field instead.

## What to check

| Cause                                                 | What to look at                                                                                      |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Wrong or expired credentials                          | The user id and password BSI is given, including the user directory on Windows                       |
| The account cannot open the app in a browser          | Sign in manually as that same user and open the app                                                  |
| The virtual proxy expects something other than a form | A proxy configured for header or certificate authentication will not present the form BSI types into |
| Password change or account lockout                    | Common cause of a job that worked for months and then stopped                                        |

::: tip This is the same check on both platforms
Qlik Sense Enterprise on Windows and Qlik Sense Cloud now both verify the login before going any
further, so a failure looks and behaves the same way on either.
:::

## If you use `--skip-login` on Qlik Sense Cloud

`--skip-login` tells Butler Sheet Icons that the browser is already signed in, so it should not enter
credentials. If that turns out not to be true — most often because the session it relies on has
expired — the old behaviour was the same silent failure: BSI captured the login screen and reported
success.

That case is now checked too:

```
CLOUD APP: not authenticated after opening the app with --skip-login. The login form's username
field ([id="1-email"]) is still on the page, so the browser is on the login screen. Continuing would
capture that screen as though it were a sheet. The session --skip-login relies on is not signed in.
Sign in to Qlik Sense Cloud in the browser profile BSI uses, or drop --skip-login and supply
credentials.
```

Sign in again in the browser profile Butler Sheet Icons uses, or stop passing `--skip-login` and let
BSI sign in itself.

## If some of your apps already have login-screen thumbnails

They were produced by a run that failed this way before the check existed. Fix the sign-in problem
and run Butler Sheet Icons again — the thumbnails are simply overwritten, and there is nothing to
clean up first.

There is no way to detect these automatically after the fact, so it is worth a look at any app whose
thumbnails were last generated by a run you did not watch.
